- 实际解码 APK 的 Manifest 与网络安全 XML：Manifest 引用生成配置，base-config 禁止明文，例外仅 localhost、127.0.0.1、10.0.2.2 和本次显式选择的 10.74.205.253，均不包含子域。未使用全局允许明文的方案。
- Docker Compose 核心服务在独立 couplelink-local 项目/网络/卷中启动成功，PostgreSQL 17 健康；局域网 IP 10.74.205.253 的 TCP 18080 实际监听，GET /healthz 返回 status=ok、api_version=1、version=1.0-r3。没有复用其他工程的数据库。

- 手机使用的数据库当前没有测试账号；浏览器测试使用另一个仅回环可访问的隔离服务和测试库。尚未连接实体手机，不能将电脑端健康检查当作手机 Wi-Fi 路由或校园网互通已验收。
- 隔离 Flutter Web → r3 Windows 独立服务 → PostgreSQL 的双会话登录、邀请、绑定、刷新、解绑及退出联调通过。长连接说明移至地址框下的独立文本，避免 Web 辅助语义层与可点击输入区域重叠；窄屏/大字号和真实输入流程已复测。

【BUG表象】：自建服务器最多两个账号且必须提供设置码；实体手机无法按普通局域网地址连接。

【真实根因】：服务端将“两人自用”写成全服务器账号数量上限并强制设置码；客户端、Android 网络规则和服务端端口监听只覆盖回环调试，遗漏局域网部署场景。

【修复方案】：移除数量及设置码校验与 UI，保留账号/情侣数据隔离；由统一构建参数生成指定 IP 的精确 HTTP 例外，默认仍禁止其他明文连接；增加指定本机 IP 的服务启动和防火墙脚本。

【修改代码】：本轮完整 r2→r3 差异在发布包 source-changes.diff。旧数据库结构无需破坏性迁移；注册门表保留兼容旧版，但 r3 不再读取或锁定它。

【回归校验】：以上静态检查、真实数据库测试、最终 APK 规则解码和实际 Compose 健康检查通过；手机访问 /healthz 与安装覆盖由用户真机验收。
