# 已确认架构与范围

手机沿用 V1.3：现代情侣空间，首页/地图/消息/时光/我的五栏，樱花恋语、薰衣草、午夜心语三主题；48dp 最小手机触摸目标、16dp 页面边距、减少动画和字体缩放。

手环沿用 V1.2：八页深色胶囊屏，首页/互动/消息/位置/宠物/纪念日/状态/设置；AstroBox 安装升级，Vela 运行，安卓 App 集成桥接。

## 1.0-r1 基线

两个 UI 应用及构建基础；实时数据和操作均为演示。手机主题、卡片顺序、隐藏配置、文案覆盖本地持久化。定位、电量及操作明确演示语义；自绘示意地图清楚标注，不依赖外部地图服务。

## 1.0-r2 基线

Flutter 新增账号控制器和安全会话存储；原生反馈通过窄 MethodChannel 接口调用 Android。Go 模块化单体使用 pgx，迁移在事务中执行。关系、成员变更和两端同步事件同事务提交；每用户事件头通过行锁递增，避免数据库普通序列在并发事务提交顺序不同时丢事件。请求逐次验证令牌、设备与关系，不依赖客户端自报权限。同步暂为手动刷新。

本轮仅用于隔离账号联调；正式私人资料接入仍以前述备份恢复、安全验收为前置条件。

## 1.0-r3 基线

注册不需要设置码，也没有全服务器两个账号的上限；每条情侣关系仍由两名用户组成，账号、设备和同步事件继续按身份隔离。旧数据库保留兼容结构，不删除用户数据。

本地服务可绑定明确的电脑私有 IPv4 地址，默认仍回环监听。Flutter 与 Android 从同一构建参数读取被明确允许的本地 HTTP 地址；Android 使用 Variant API 生成精确主机例外，base-config 保持禁止明文，不自动跟随重定向。公网仍通过 HTTPS 接入。

## 1.0-r4 基线

Flutter/Riverpod 使用 Drift/SQLite 持久化按服务器、账号和情侣关系隔离的队列、草稿、消息与游标。Go/PostgreSQL 管理幂等消息、关系内顺序和送达回执；写入与实时通知 outbox 同事务提交。Centrifugo 只发刷新提醒，API 复核当前权限后查询正文；离线与实时中断用游标补齐。细节、选型与容量边界见 CHAT.md。

密码最少 8 位，允许纯数字，客户端/服务端/中文与英文提示同步；仍使用 Argon2id 存储。

## 当前 1.0-r5

互动由服务器事务保存、限频并在关系锁下验证，固定 ID 幂等去重；对方客户端前台领取，领取操作保证多个设备不会重复执行，过期互动不能领取。用户控制是否请求振动和响铃，后者默认关闭，系统权限和勿扰仍生效。结果区分接收及实际向系统请求、阻止、不支持和失败。在线通知触发拉取，前台 2 秒轮询兜底；后台推送尚未接入。

## 后续

Flutter + Riverpod；Android Kotlin 能力模块；Go 模块化单体；PostgreSQL/PostGIS；Centrifugo；SQLite/Drift 离线队列；Docker Compose。

业务写入、同步事件和 outbox 同一事务提交。Go 管理持久化与授权。地图、推送、定位提供方可替换。

位置分享期限、精度、个人轨迹记录独立建模。撤销本机立即停止，服务端收到后拒绝读取；离线对端缓存不能保证立即删除。离线点附来源设备和授权版本，历史点不能覆盖最新位置，旧关系授权不能用于新绑定。

互动用稳定 action_id 识别，文案只影响显示。真实互动需要幂等 ID、有效期、接收方许可和执行回执，过期响铃不重放。隐藏卡片仅调整布局，关闭共享为独立权限操作。

正式私人数据接入前完成备份恢复、解绑撤权、日志脱敏。心率及手环后台能力按 EXP 验证。
