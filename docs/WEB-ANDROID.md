# CoupleLink 1.0-r9 Web 安卓客户端

## r9 通知与振动修复

安装 `CoupleLink-Android-1.0-r9.apk`，可覆盖 r8，沿用账号和本机缓存。登录、绑定及恢复会话后：通知已获准则默认启动后台接收；尚未授权时自动申请一次，或点击“一键开启消息提醒”。不再把后台接收作为单独的手动开关。拒绝授权后不会反复弹窗；系统关闭通知时停止接收，恢复授权并回到应用后重新启用。

本轮根因：r8 后台接收默认关闭且与系统许可独立，用户启用后已确认恢复通知；互动通知又被设置为静默/无振动，反馈依赖独立 Vibrator/Ringtone 调用，前后台路径不一致。r9 前后台统一由 NotificationManager 执行接收设置对应的视觉/振动/响铃通知，避免一次互动重复振动或把静默类别当成振动提醒。过期事件及用户关闭的接收反馈保持静默；系统关闭通知时不会用独立振动绕过该设置。

“测试震动”现在使用同一互动通知路径，不向另一方或服务器发送测试事件。完成后显示系统通知权限、振动器、振动操作许可（无法读取则明确显示未知）、声音/勿扰模式、服务运行状态，以及每个类别的实际重要性、声音和振动设置。可直接打开对应类别，底部可长按复制不含聊天正文/令牌的诊断结果。

新增振动和响铃类别不会覆盖旧类别的用户阻止/降级决定，也不覆盖新类别中用户修改的设置。若旧“情侣互动”类别已被关闭或降级，先在该类别及相应提醒类别中检查设置。Android 7 补齐 Builder 的声音/振动设置；Android 8+ 以实际渠道配置为准。厂商“横幅/悬浮”开关、锁屏显示和通知冷却仍由系统控制，不申请悬浮窗权限、不绕过勿扰。

手机已打开通知权限不等于物理马达一定动作；`requested` 仅表示请求已提交。当前没有真机通过 ADB 连接，本轮不能断言该手机的振动已经恢复；请安装后在“我的 → 测试震动”实测，仍无反馈时提供诊断结果。

以下 r8 说明保留作迁移历史，其中“主动开启后台接收”已被上述默认接收取代。

## 安装与迁移

安装 `CoupleLink-Android-1.0-r8.apk`。包名和签名沿用旧版，可覆盖安装；首次切换到 Web 客户端需要重新登录。服务端账号、绑定与已发送聊天记录保留，不需要重建服务器数据库。旧 Flutter 的本机草稿、未发送消息及偏好不会自动迁移；升级前请先在旧版发送待发消息。不要卸载应用来解决迁移问题。

页面随 APK 打包，打开应用不依赖网页服务器。系统字体用于新客户端，未附带旧版 Flutter 引擎或字体文件。手环仍为独立 Vela 测试版，没有接入真实双向通信。

## 已接入

- 登录、注册、邀请、绑定与解绑，复用 Go API v1。密码 8–128 位，不要求大小写或符号组合。
- 文字聊天：IndexedDB 持久队列、固定消息 ID 重试、按服务器序号同步、持久化后发送回执、未读红点、进入消息页清除红点。
- 戳一下、想你了、抱抱、震动和响铃：接收方设置、系统静音/勿扰、服务端有效期、单次认领、去重及限流。
- 安卓系统通知：权限申请、消息高重要性渠道、点击跳转消息页、通知测试和系统设置入口。通知正文默认不包含聊天明文。
- 用户主动开启的后台接收：原生 dataSync 前台服务、常驻通知、5 秒轮询，读取 Keystore 加密会话；不会依赖冻结后的 WebView 执行 JavaScript。
- 多个地址保存、测试、手动切换；切换时停止后台连接、清除旧令牌并重新登录。不会自动把令牌发到备用服务器。
- 三个主题、简中/英文、减少动画和表单无障碍标签。原生后台通知文案按 Android 系统语言选择。

## 当前边界

当前前台采用 2 秒轮询，尚未在新客户端接入 Centrifugo WebSocket；不承诺离线或后台秒级到达。聊天历史从游标分批恢复，队列保存失败会阻止网络发送并显示错误。

系统授权与通知渠道控制顶部弹窗、声音和角标；不能强制覆盖勿扰或用户关闭的通知。模拟器只能验证系统调用和通知发布，不能证明真机马达、扬声器及厂商后台策略的实际效果。Android 15+ 的 dataSync 时限、强制停止和省电限制依然适用；到期服务停止，重新打开应用后可再次主动开启。

地图、轨迹、相册、宠物和完整纪念日编辑尚未迁移，界面明确说明未接入；恋爱天数来自服务器。自定义语言包编辑/导入及自动地址故障切换不在本轮。

HTTP 保持之前获准构建的精确地址范围：`192.168.137.1`、`10.74.205.253`、`localhost`、`127.0.0.1`、`10.0.2.2`；HTTPS 支持其他服务器。HTTP 页面显示未加密提示。任意公网 HTTP 此前被自动审核拒绝，本轮没有通过新壳绕过限制。

## 调研与选择

- Capacitor：<https://github.com/ionic-team/capacitor>，WebView + 原生插件，持续维护；复用其安卓生命周期和插件框架，不复制其他情侣应用源码。
- 通知授权：<https://capacitorjs.com/docs/apis/local-notifications>；本项目实现小型原生桥接，通知仍受 Android 权限与渠道管理。
- Wails 安卓仍标记实验性：<https://wails.io/guides/mobile/android/>，暂不作为稳定安卓主线。
- Go Mobile：<https://go.dev/wiki/Mobile>，可以生成原生库，但增加 NDK 与绑定维护。本轮 Go 保留在服务端，不额外在手机启动 Go HTTP 服务。

## 构建

Node 24、JDK 21、Android SDK 36；依赖固定在 `apps/mobile-web/package-lock.json`。Gradle 8.14.3 / AGP 8.13.0，最低 Android API 24；系统 WebView 必须符合 Capacitor 8 要求。

```powershell
npm.cmd --prefix apps/mobile-web ci --no-audit --no-fund
npm.cmd --prefix apps/mobile-web test
./scripts/build-web-android.ps1 -JavaHome '你的 JDK21 路径'
```

先设置 Android SDK 路径（`ANDROID_HOME` 或该工程的 `android/local.properties`）。Release 使用现有 `.secrets/signing.properties` 与签名密钥，不重新生成；这些文件不会进入发布包。产物为 `apps/mobile-web/android/app/build/outputs/apk/release/app-release.apk`。

本机浏览器预览：`npm.cmd --prefix apps/mobile-web run dev`。浏览器跨域访问需在 Go 服务端配置明确的预览 Origin；浏览器会话仅保存在内存，系统反馈需安卓客户端。发布包关闭 WebView 调试和桥接参数日志，原生网络拒绝重定向，令牌使用 Android Keystore AES-GCM 存储。
