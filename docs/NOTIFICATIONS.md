“测试震动”和前台互动反馈改为通知用途（`USAGE_NOTIFICATION`）并带显式波形，不再受“系统触感”触感开关影响；通知类别升级为 `couplelink_alerts_v2` 并显式设置振动模式，解决“有通知、有提示音、无振动”。真机证据与边界见[FEEDBACK.md](FEEDBACK.md)。

# 直接震动测试修正

“测试震动”现已直接调用原生Vibrator，不通过通知或申请通知权限。收到消息和远程互动继续使用统一通知类别。详见[FEEDBACK.md](FEEDBACK.md)。手机实际振动未验收。

# 1.0-r9 本地修正

当前仅注册“消息提醒”一个类别，启动时清理旧的消息/互动/声振/后台类别；不再提供应用内独立声振开关。聊天、互动和纪念日遵守同一系统渠道设置，后台状态自身静默。迁移保留已有系统偏好，不保证硬件振动已修复。新增日期与搜索见 [MEMORIES.md](MEMORIES.md)。以下为此前版本记录。

# CoupleLink 1.0-r7 通知与地址

## 让手机收到通知

1. 两台手机安装同签名 r7，登录并绑定情侣。进入“我的”中的“系统通知”，点击“开启通知”；在 Android 授权窗口中允许。
2. 点击“测试通知”，查看通知栏。如果没有弹出，在“打开系统通知设置”中检查允许通知、悬浮通知、声音、振动和对应渠道。系统及手机厂商决定实际显示方式。
3. 希望退到后台时继续接收，点击“开启后台接收”。手机会显示一条常驻连接通知；可在同一位置关闭。前台通过原实时连接接收，后台使用已有 API 每 5 秒检查，网络不稳定时重试。系统省电、网络、强制停止或 Android 15 的 dataSync 服务时限可能中断，不能保证秒级和永久在线。
4. 收到对方消息时，底部“消息”入口出现红点；进入消息页会清除本机红点。送达回执与阅读状态是两件事；红点是本机状态，不代表跨设备已读。
5. 互动振动调用 Android Vibrator 并先检查设备能力、静音和勿扰；是否实际振动仍受设备和系统设置影响。用户可在“我的”分别开关互动振动和响铃。后台互动通过系统通知渠道反馈，未过期的互动只能由一台设备领取。

通知默认只显示“伴侣发来了一条消息”，不在锁屏中展示聊天正文。开启系统通知或后台连接会请求相应系统许可，拒绝权限时不会假装成功。

## 保存多个服务器地址

在“我的 → 服务器”添加多个完整地址，逐个点击测试。点击“使用并登录”会清除本机旧会话并打开登录页，不会把旧服务器的令牌转发到新地址；需在新地址重新登录。各地址的聊天缓存和待发送消息按地址隔离，不进行自动迁移或自动故障切换。

本次 Android 包可对 `192.168.137.1` 和 `10.74.205.253` 使用 HTTP，其他地址仍需 HTTPS。当前电脑热点服务器是 `http://192.168.137.1:18080`，原 Wi-Fi 地址需要先切换服务器监听。用户已要求支持任意公网 HTTP，但自动审核曾拒绝该构建；HTTP 不加密账号、密码或聊天内容。

## 数据迁移与验证

本机聊天 SQLite 从版本 1 升级到版本 2，保留原消息、草稿及游标，只增加本机已读游标。测试覆盖旧库升级、未读红点、本机已读状态、前后台游标、服务器切换及原有聊天和互动。系统通知、振动、后台长期运行、悬浮通知及厂商省电限制仍需 Android 真机验收。
