# CoupleLink 1.0-r4 文字聊天

用户已确认完整文字聊天 MVP；保留 Flutter、Go/PostgreSQL，自建服务。

## 已调研并确认的选择

- Togetherly（https://github.com/THET1ME-1/Togetherly）：Flutter、PocketBase、Centrifugo、Sembast，调研时 2026-10-20 仍有发布；参考本机队列与在线提醒分层。GPL-3.0，未复制其代码，也不引入其完整业务与依赖覆盖配置。
- Centrifugo（https://github.com/centrifugal/centrifugo）：Apache-2.0，采用 6.10.2。只负责在线提醒，消息持久性、关系权限和历史仍在 Go/PostgreSQL。注意其环境变量列表使用空格分隔，客户端历史恢复不能代替数据库消息游标。
- Drift（https://github.com/simolus3/drift）：MIT，固定 2.35.1，本地 SQLite 队列与游标可在一个事务内更新。Web 必须匹配 sqlite3.wasm 与 worker，Android 使用原生 SQLite；两种平台分别验证。
- Tinode（https://github.com/tinode/chat）：Go 完整 IM，GPL-3.0，参考服务端顺序、设备回执与权限检查。当前已有账号和关系服务，不引入另一套账号系统。

## 消息链路

输入 → 先写本机 SQLite（稳定 UUID）→ 经过身份及关系校验 → PostgreSQL 同一事务写消息、关系内序号、同步事件、通知发件箱 → Centrifugo 发送无正文的刷新提醒 → 接收端按消息游标拉取 → 本机落盘 → 送达回执。

实时连接失败仍每 2 秒在前台补齐；回到前台和重新连接也会同步。通知失败留在服务端发件箱重试。重复消息 ID 与相同内容返回原记录；同一 ID 修改内容会拒绝。服务端按关系顺序分页，每页最多 100 条。

## 实际能力和边界

- 文本每条最多 4000 Unicode 字符，拒绝空白、空内容和 NUL。当前没有图片、语音、已读、后台系统推送或端到端加密；消息正文保存在用户自建数据库及本机缓存。
- 状态：待发送＝仅本机排队；已发送＝服务器接受；已送达＝对方至少一个客户端保存并确认。已送达不代表阅读。
- 本机容量按服务器地址、账号、关系隔离。每个关系默认最多 2000 条未发送、16 MiB 未发正文；最多缓存 2000 条已接受记录，旧记录可联网重新查询。上限可由 ChatStore 构造配置，未发送内容不会为腾出空间而被自动删除。服务端尚未提供消息保留期清理。
- 草稿与待发送消息先落盘；Android 令牌在系统安全存储，离线重启可恢复已验证身份的缓存。浏览器令牌仅内存，刷新后需重新登录；浏览器存储可被系统或用户清除。
- 退出/丢失认证会隐藏原账号缓存；再次验证相同服务器、账号和关系后才可恢复队列。没有跨账号发送。客户端确认同账号的关系变更后，清除旧关系草稿、缓存与未发消息；解绑不自动删除服务端历史，旧关系不可继续访问。
- API 每次事务内重新检查会话和当前关系，使用与解绑相同的双用户锁；解绑或设备撤销后新请求即拒绝。实时 JWT 短时有效，撤销会排入断连任务；通知只含刷新标记，正文仍必须通过重新鉴权的 API 获取。
- Android 后台会暂停前台同步；暂不保证后台送达或系统通知。返回前台后补齐。服务器时间决定消息排序，客户端时钟不参与权限和顺序判断。

## 新增接口

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| POST | /messages | id、couple_id、body；幂等写入 |
| GET | /messages | couple_id，after 增量或 before 历史游标 |
| POST | /messages/receipts | couple_id、through；设备持久化确认 |
| POST | /realtime/token | 当前有效会话的短时 JWT |
| GET | /connection/websocket | Go 代理内部实时服务 |

## 开发顺序及验证

本轮按数据库与幂等接口 → 本机队列与恢复 → 在线提醒与回执 → 双端/断网/解绑 → 签名发布实施。自动回归覆盖真实 PostgreSQL、真实 SQLite 文件、响应丢失后重试、分页和关系撤销；桌面双端验证使用隔离数据库。构建和桌面验证不代替 Android 真机验收。
